- **D5 (minor residuals)** Unbind is enabled like ImGui and the combo Input has `maxLength=127` (original 128-char buffer incl. NUL). Remaining intentional differences: Capture button disabled while capturing; Esc closes the dialog when not capturing (the original ImGui modal stayed open).
- **D6 (resolved)** `shell.selectPanel` rejects unregistered ids with `unknown_panel`; registered failed/no-panel plugins stay selectable, matching the original menu/sidebar semantics (content pane explains). The plugin-ABI `RequestShowPanel` validation is unchanged.
- **D7 (residual)** `bridge.closed` now sets `connected=false` + error and App shows a "Bridge disconnected" boot screen; there is still no auto-reconnect, and the store ignores `shell.ready` (initial state comes from the seven start queries).
- **D8 (open, minor)** The WebView2 environment language is fixed at init; React strings switch live but the browser locale does not.
- **D9 (residual)** Init, virtual-host mapping, user-data creation, and navigation failures now fail over to ImGui (generation-guarded); `NewWindowRequested` is handled and permissions denied. Remaining gap: no `ProcessFailed`/renderer-gone handler - a renderer crash after ready is not recovered automatically.
- **D10 (open)** The Settings plugin-enable list is not refreshed when `snapshot.pluginFiles` changes after the initial load (`settings.changed` is emitted only on writes; `lastSettingsSig_` remains unused).
- **D11 (open, minor)** The web-active loop branch has no frame-gap probe (WD-17 diagnostics exist only on the ImGui branch); clipboard refresh is intentionally skipped there (WebView2 owns its clipboard).
- **D12 (resolved)** `IsDocumentReady()` is defined and gates both visibility and the web-manager branch; `Focus()` is called on the hidden-to-visible transition.

## 10. Hotkey capture & dispatch semantics (must-preserve list)

These are behavioral contracts, not widgets. Sources: src/Hotkeys.cpp/.hpp, src/DesktopUi.cpp:766-831, src/PluginHost.cpp:679-749.

1. **Reserved F1** everywhere: plugin registration default or effective override = F1 → `E_CONFLICT` + warn (src/Hotkeys.cpp:383, src/PluginHost.cpp:474-477); `SetOverride(F1)` → conflict (:400); reset to an F1 default → conflict (:428); INI overrides naming F1 are skipped at load (:345-348); capture flags F1 invalid (src/DesktopUi.cpp:791, 815).
2. **Capture suppression**: `SetCaptureActive(true)` suppresses ALL plugin dispatch and the F1 toggle while capturing; on release every binding + manager key is latched `down=true` so the captured press can never dispatch — a released sample is required first (src/Hotkeys.cpp:445-455, 488, 491). Apply/Reset also latch the edited binding (src/Hotkeys.cpp:413, 438).
3. **Capture cancel paths**: Esc during capture cancels capture only (editor stays); foreground window ≠ control window stops capture (src/DesktopUi.cpp:775, 799); minimize/kill-focus/app-deactivate/hide/close/panel-switch close the whole editor (HK-20). WebView2 focus is not Win32 focus — the native side must keep owning these transitions.
4. **Capture mechanics**: `GetAsyncKeyState` edge scan of VK 8..255, modifier-only keys skipped, live Ctrl/Shift/Alt/Win modifier mask, capture button seeds held-key state (src/DesktopUi.cpp:773-793, 805-808). DOM keydown cannot reproduce global async state or the latch; keep capture native and push results to React.
5. **Combo grammar**: `+`-separated, trimmed, case-insensitive; modifiers CTRL/CONTROL, SHIFT, ALT, WIN; exactly one primary key: A–Z, 0–9, F1–F24, `VK<n>` (1–254, round-trips numpad/media keys), or named keys (SPACE, TAB, ENTER/RETURN, ESC/ESCAPE, BACKSPACE, INSERT, DELETE/DEL, HOME, END, PAGEUP, PAGEDOWN, arrows, COMMA, PERIOD, MINUS, PLUS/EQUAL, SLASH, BACKSLASH, SEMICOLON, QUOTE, LEFTBRACKET, RIGHTBRACKET, GRAVE/TILDE) — src/Hotkeys.cpp:182-282. `ValidCombo`: primary in [VK_BACK, 254], never a modifier key, modifier mask limited to the four bits (:238-248). Canonical format `Ctrl+Shift+Alt+Win+<KEY>`, `<unbound>` for 0 (:284-307). React must display exactly this format; parsing stays native.
6. **Conflicts**: same vk+mods claimed by two different owners → both marked conflicted, neither dispatches; same-owner duplicates and unbound rows excluded; transition logged once with the exact ids+combos and "Rebind one in the F1 manager" (src/Hotkeys.cpp:127-151). The State column is the only in-UI conflict surface.
7. **Identity & INI format**: writes use `v2:<hex(pluginId)>:<hex(actionId)` (case-insensitive key, hex preserves exact bytes); legacy lowercased `plugin.action` aliases are read-only and apply only when unambiguous across registered bindings; `<default>` on a v2 key masks legacy values and follows the plugin default; ambiguous legacy overrides are ignored with a warn, original INI preserved (src/Hotkeys.cpp:45-93, 155-180, 309-356). Section read cap 32768 chars — over-limit means NO partial overrides load (:312-321). Unparsable/F1 override values are skipped, never silently unbind (:345-348).
8. **Write-through order**: INI write first; only on success mutate override cache + registry and recompute conflicts; failure leaves live state untouched and surfaces the save-failed banner (src/Hotkeys.cpp:396-443, src/Hotkeys.hpp:54-57).
9. **Dispatch environment**: dedicated poller thread at ~12 ms; foreground must be the host window or `UnityWndClass` of the same process (shell dialogs in-process are NOT input targets); host text-input focus suppresses everything; F1 edge tracked even when unfocused so returning never replays a press; plugin actions are enqueued to the Unity main thread, never run on the poller; F1 toggle is posted to the UI window immediately (src/PluginHost.cpp:690-725, src/Hotkeys.cpp:477-504).
10. **Re-registration**: same owner+actionId replaces the binding; registration recomputes overrides/conflicts for everyone from declared defaults so order never matters; a key change latches `down=true` (src/Hotkeys.cpp:155-180, 358-394).

## 12. Migration design decisions & ambiguities (resolve before implementation)

1. **ImGui plugin panels vs WebView2 (PP-06)** — the frozen ABI (`include/GakuPlugin.h:130-147, 287-290`) hands plugins the host ImGui context + allocators inside `onDesktopUi`. A WebView2 content pane cannot render ImGui draw lists. **Resolved (implementation): hybrid swap.** The WebView2 child covers the client area only while the Manager is selected and the view is ready; any plugin selection hides the child and renders the full ImGui frame, so `bind`'s fingerprint gate (src/DesktopUi.cpp:349-361) and the file-drop/dialog/hotkey services keep their exact admission rules. See PP-06 and [webview2-migration-notes.md](webview2-migration-notes.md).
2. **Log page is NEW scope, not a migration row** — the current Manager has no log viewer (§15). A React log page needs a new native tap (in-memory ring or file tailer); nothing today buffers records for UI reads. **Resolved: stays out of scope; LOG-01...LOG-08 are `blocked` and no log bridge was added.**
3. **Scale-limit banner (AP-01)** — WebView2 has no font-atlas ceiling; decide whether to retire the banner or keep an equivalent guard for the native ImGui panel surface if one survives. **Resolved: retained.** `ServiceAppearance` keeps the ImGui font-atlas build for the plugin surface, so `scaleLimited` still reflects a real rejection and rides `appearance.changed`; the React banner renders it (frontend/src/pages/AppearancePage.tsx).
4. **Dormant strings/fields** — `Key::ConfigFile`, `Key::Saved`, `Key::DefaultBinding`, `Key::CustomBinding` (src/ManagerStrings.hpp:31-32) are translated but rendered nowhere; `Hotkeys::Row.overridden` (src/Hotkeys.hpp:41) is computed but not displayed (State column shows only unbound/conflict/active, src/DesktopUi.cpp:848). **Resolved: all 65 keys are served by `strings.get` (`kStringKeys`, src/ManagerBackend.cpp:61-95) and `overridden` is transported in hotkey rows; neither is rendered, matching the original. No new UI was invented.**
5. **No plugin CRUD** — there is no rescan/import/export/delete/live-toggle API anywhere (§14). Any React affordance beyond the next-start INI checkboxes would be new native work, not a port. **Resolved: no CRUD added; the Settings page remains next-start INI toggles.**
6. **No single-instance guard** — none exists today (only in-process worker latches, src/DesktopUi.cpp:1215-1222); do not add one silently. **Resolved: none added.**
7. **DPI awareness** — no loader manifest (`GenerateManifest=false`, Directory.Build.props:25); the window relies on the game process's DPI context + `WM_DPICHANGED`. WebView2 initialization must match the host process DPI awareness or scaling will double-apply. **Resolved (partially): the WebView2 child inherits the host process DPI context; `uiScale` applies as CSS `zoom` and DPI is handled by WebView2 rasterization (frontend/src/lib/appHooks.ts). D1 (DPI-only changes emit no `appearance.changed`) remains open; DPI acceptance is manual.**
8. **Concurrent work** — an untracked `deps/webview2/` appeared in this worktree during the audit (another agent's staging). **Update: `deps/webview2/` and `deps/nlohmann/` are now the vendored inputs of the implementation; `Directory.Build.props` and `GakuLoader.vcxproj` were modified by the native workstream (not by this documentation pass).**

## 14. Plugin list operations & authoritative state owners

There is no `PluginHost` class: `src/PluginHost.cpp` implements the free functions declared in `src/Host.hpp:16-121`.

- **Live model**: `g_plugins : vector<LoadedPlugin>` (src/PluginHost.cpp:45; fields src/Host.hpp:18-29 — dllPath, handle, id, name, version, descriptor, host, state, owner, activated, runtimeReady, failed; **no enabled/description/author field**). `g_pluginFiles` = discovered filenames incl. disabled/rejected (src/PluginHost.cpp:36, src/Host.hpp:72).
- **UI read path**: only `SnapshotDesktopHost` (atomic shared_ptr copy, src/PluginHost.cpp:61-74, 1127-1133). `GetLoadedPlugins()` returns the live vector without a lock (src/PluginHost.cpp:1168) — the bridge must NOT use it.
- **Discovery** (one-shot `ActivatePlugins`, src/PluginHost.cpp:911-999): non-recursive scan of `GakuLoader/plugins`; regular files, extension `.dll`, no leading dot; case-insensitive exclusions `GakuBurstBridge.dll`, `GakuMotion.VmdImporter.Native.dll` (auxiliary libs, :933-936); sorted; `[plugins]` flag checked before `LoadLibraryExW(LOAD_WITH_ALTERED_SEARCH_PATH)`; required export `GakuPlugin_Query`; exact descriptor ABI/size + non-empty id + name + activate; duplicate ids rejected; load/query/duplicate failures FreeLibrary and continue; activation failure → `failed=true` + owner retired, entry retained. No rescan exists.
- **Lifecycle transitions republish the snapshot**: activation per plugin (:992), runtime-ready per plugin (:1004-1026), tick/actor/desktop exceptions (:1082, 1102, 1143), shutdown per plugin (:776). `shuttingDown` in the snapshot is overridden from the live atomic on read (:1131) — UI gives it precedence (footer does, src/DesktopUi.cpp:1008).
- **`runtimeReady` semantics**: IL2CPP became resolvable and runtime callbacks dispatched — NOT proof that frame/actor hooks are installed (src/PluginHost.cpp:1000-1031; hook installation lives in src/GameHook.cpp). Keep the string "waiting for IL2CPP", not "hooks active".
- **Owner retirement** (src/PluginHost.cpp:417-451): closes acceptance, retires paths, cancels dialogs (`DesktopDialogs::CancelOwner`), removes hotkeys/actor entries/services/tasks, disables hook leases (batched during exit). Every plugin-facing service wrapper refuses retired owners with `GAKU_E_SHUTTING_DOWN`.
- **Startup order** (src/Main.cpp:31-79): DllMain (game-process check `gakumas.exe`) → startup thread pins module → optional console → `Initialize` → `DesktopUi::Initialize` (services must exist before activation) → `ActivatePlugins` → `StartHookThread` + `StartQuitGuard` even if the try failed.
- **Shutdown order** (game close): QuitGuard subclasses same-process `UnityWndClass`, swallows WM_CLOSE and requests Unity quit (src/QuitGuard.cpp:151-163; message `WM_APP+0x5171`, src/UnityQuit.cpp:53, 97) → on Unity main thread host teardown runs BEFORE `Application.Quit` (src/UnityQuit.cpp:55-95): `DisableAllHooksForExit` (src/GameHook.cpp:486-504) calls `DesktopUi::Shutdown` first (drain render callbacks before the lifecycle mutex, :497), then host `Shutdown` → `ShutdownOnMainThread` runs plugin `shutdown` in reverse activation order, retires owners (src/PluginHost.cpp:751-789), `CloseLog` (:1165; late lines reopen append). Watchdog budgets: 15 s teardown / 8 s post-quit / 40 s ceiling, then force-terminate (src/QuitGuard.cpp:179-181, 208-246). The WebView2 shell must fit inside `DesktopUi::Shutdown`'s 5 s worker wait (WD-12) or it will be reported as resident.

## 16. Trickiest semantics not to lose (checklist)

1. F1 three-way toggle (show / hide-only-from-Manager / switch-to-Manager) and its independence from game frames (WD-04).
2. Close ≠ exit: hide-to-tray with minimize fallback when the tray refuses the icon; TaskbarCreated recovery (WD-03, TR-02, WD-14).
3. Hotkey capture latch: ending capture must never dispatch the captured press; every focus/minimize/hide path releases capture (HK-16, HK-20, §10.2-3).
4. Text-input suppression: React input focus must drive `WantsTextInput` equivalent or typing fires plugin hotkeys (WD-16).
5. Reserved-F1 enforcement in every write path incl. reset-to-default and INI load (§10.1).
6. v2 hex identity keys + legacy alias ambiguity rules + `<default>` masking; INI-first write ordering with rollback-free failure (banner + unchanged registry) (§10.7-8, SH-12).
7. Deferred manager actions: all config/hotkey/language disk I/O runs outside the plugin callback gate; the bridge must never do slow I/O while holding `g_callbacks` (src/DesktopUi.cpp:1071; src/PluginHost.cpp:50).
8. Manager renders gate-free; plugin panels keep their last image under contention; main-thread waiters starve desktop frames by design (PP-05; src/PluginHost.cpp:1107-1126).
9. Drop mailbox: per-frame target expiry, single batch, owner-scoped consume-once, selected-panel-only routing, host-client-pixel coordinates, UIPI integrity gating with WM_DROPFILES fallback and cursor heuristic (FD-01…FD-09). DOM drop coordinates need explicit translation to the frozen contract.
10. File dialogs: serial native pump outside all gates, one ticket/owner, 16 total, cancel via timer→WM_CLOSE to the dialog's own HWND, owner retirement cancels tickets (DL-01…DL-07).
11. Clipboard sequence validation + writes outside the gate (WD-15).
12. Appearance: atomic publish to plugins, DPI×scale composition, atlas-limit revert, next-frame apply, immediate persistence with partial-write possibility (AP-01…AP-03, §13).
13. Language: write-then-publish, tray tooltip refresh, poll-based plugin propagation, system-default mapping incl. zh-HK/MO (AP-04, L10N-03/04).
14. Save-failed banner is sticky and global to the Manager page; checkboxes roll back individually (SH-12, ST-03/04/08).
15. Snapshot-only reads (`SnapshotDesktopHost`), `shuttingDown` precedence, `runtimeReady` ≠ hooks installed, failed plugins keep spinner + failed badge (§14, PL-06/07).
16. Shutdown fits the 5 s DesktopUi worker wait inside the QuitGuard 15 s teardown budget; UI teardown precedes plugin shutdown; nothing under loader lock (§14, WD-12).
17. Exception containment everywhere: UI worker, plugin callbacks, dialog show — a UI failure must never take down the game (WD-11, PP-08, DL-04).
18. Localization parity: all 65 keys × 4 languages, exact combo/version formatting, localized tray tooltip and native tray menu (§11).
